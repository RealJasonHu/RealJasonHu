# Profile maintenance conventions

## Identity

- Use **Jason Hu** for the owner's public display name, personal bylines, image alt text, SVG titles/descriptions, and self-attribution in this repository.
- Keep the GitHub account and repository owner identifier **RealJasonHu** unchanged in URLs and code. A display name is not a username or package scope.
- Do not change functioning email addresses, other people's names, upstream ownership, or third-party copyright notices when standardizing the owner's display name.
- These conventions do not change GitHub account settings or historical Git author metadata. Do not rewrite history or force-push as part of a profile edit.

## Evidence and project status

- Read the current default-branch README and project documentation before refreshing a project description.
- Distinguish original projects, upstream pull requests, and review contributions. A fork is not an original project; an open pull request is not a merged contribution.
- Verify pull-request status from the upstream thread and date any status snapshot.
- Preserve qualifications on demo results, experimental scope, and model accuracy. Do not turn fixture results into general benchmarks.
- Do not publish private research details, credentials, contact details, academic outcomes, or publication claims without explicit supporting information and authorization.

## Presentation and safe edits

- Preserve the profile's restrained dark-banner visual language, readable English text, and concise Chinese section labels.
- Prefer real project screenshots, maintained repository assets, accessible alt text, and direct source/demo links over decorative counters or unsupported badges.
- Read the latest file before writing. If a write conflicts with a newer commit, reread and preserve concurrent changes rather than overwriting them blindly.
- Keep profile edits scoped to presentation, links, and accurate project summaries. Do not change project behavior, dependencies, releases, or upstream code as part of decoration.
